01 · Decision

What changes from v1.

The original concept is strong. The change is sequencing. We do not build the full membership first. We prove that people return to the relationship after the Blueprint.

The original PRD correctly identifies the core insight: the product is not the Blueprint; the Blueprint is the onboarding ritual. The product is the ongoing relationship with a stylist that remembers the member’s body geometry, colour profile, facial architecture, preferences, wardrobe, and past questions.

The revision keeps that insight but removes the operational overbuild. Version 1 should not launch as a complete “nine-feature platform.” It should launch as a retention experiment wrapped in a premium annual membership.

Founder Decision
Build the smallest product that can prove weekly retention, not the biggest product that can impress a pitch deck.
Annual-first
Limited usage
Admin-tracked
Beta before scale
No unlimited chat

05 · Product V1

The member product should feel complete, but be operationally small.

The goal of v1 is to prove: they complete the intake, they open the letter, they ask questions, they upload photos, and they want to renew.

V1 · 01
Free Style Archetype Quiz
15–18 questions. Segments by body geometry, colour risk, modesty preference, work/social lifestyle, budget, climate, and frustration.
V1 · 02
Full Blueprint
Paid member receives full diagnostic: silhouette, colour, facial architecture, 10–15 outfit rules, avoid list, and starter formulas.
V1 · 03
Sunday Style Letter
Weekly personalised drop with visual outfit ideas, one trend filter, one wardrobe gap, and one rule tied to her profile.
V1 · 04
Stylist Questions
20 monthly text questions. Designed for specific use cases: “what do I wear to X,” “does this suit me,” “which colour works?”
V1 · 05

06 · Admin OS

Admin side: what ICONIK needs to track everything.

The admin dashboard is not a back-office tool. It is the control room for funnel conversion, client delivery, quality, retention, and enterprise value.

Admin · 01
Executive Dashboard
Top-level view for founder: revenue, ARR, MRR, new members, CAC, refunds, overdue Blueprints, open support tickets, churn risk, and funnel leak by source.
  • Today / 7-day / 30-day filters
  • Revenue by plan and country
  • Organic vs paid member split
  • At-risk members and renewal pipeline
Admin · 02
Funnel Analytics
Tracks every conversion step from Reel source to paid member. Must show where each content angle leaks.
  • Reel ID, hook, angle, CTA, country
  • DM clicks, quiz starts, quiz completions
  • Email capture and checkout started
  • Purchase rate by archetype and pain point
Admin · 03
Lead CRM
Every quiz taker becomes a lead profile with source, archetype, intent score, emails opened, result viewed, checkout activity, and last touch.
  • Lead score 0–100
  • Segment tags: apple, pear, modest, office, colour
  • Abandoned checkout queue
  • Manual note field for founder/ops
Admin · 04
Member Profile
Single source of truth for each paid member. This is what support, stylist QA, and retention teams open before acting.
  • Plan, payment, renewal date, country
  • Blueprint summary and images
  • Usage: questions, photo checks, letters opened
  • Health score and risk reason
Admin · 05
Intake + Photo Review Queue
Tracks whether the customer submitted usable photos and completed all required inputs. Prevents broken Blueprints.
  • Status: missing, submitted, rejected, approved
  • Photo quality checklist
  • Auto-email for bad/missing images
  • Side-profile request template
Admin · 06
Blueprint Production Queue
Kanban-style delivery queue for paid Blueprints with SLA timers and human review states.
  • Pending generation
  • Generated draft
  • Stylist review needed
  • Approved, delivered, revised
Admin · 07
Sunday Letter Engine
Shows upcoming letters by timezone, member cohort, archetype, delivery status, open rate, click rate, and chat follow-through.
  • Preview each generated letter
  • Hold/rewrite if generic
  • Delivery failure alerts
  • Letter format rotation tracking
Admin · 08
Chat + Escalation Review
Monitors chat quality, memory recall, photo responses, usage limits, and any messages requiring human review.
  • Flagged response queue
  • Low-confidence answer alerts
  • Body-sensitive language review
  • Random QA sample audit
Admin · 09
Retention Dashboard
Identifies members likely to cancel before they cancel. Uses behaviour, not vibes.
  • No login in 14 days
  • No letter opens in 3 weeks
  • No chat/photo usage in 30 days
  • Cancellation intent and win-back state
Admin · 10
Billing + Refunds
Stripe-connected view for payment status, failed payments, dunning, refunds, plan changes, coupons, and renewal dates.
  • Payment failed queue
  • Refund reason codes
  • Coupon attribution
  • MRR/ARR movement log
Admin · 11
Support Inbox
A lightweight ticketing layer connected to member profile and delivery status. No customer should get lost in Gmail/DMs.
  • Ticket owner and priority
  • SLA timer
  • Template replies
  • Escalation to founder/stylist
Admin · 12
QA + Voice Audit
Ensures the product does not sound like a generic chatbot and does not give unsafe or unhelpful styling feedback.
  • Score responses 1–5
  • Track AI-tell phrases
  • Memory recall pass/fail
  • Stylist specificity score

11 · Tech Stack

Recommended architecture.

Keep the stack simple. The complexity should live in the product logic and admin workflows, not infrastructure.

Layer 01
Frontend
Next.js app on Vercel. Routes: /stylist/quiz, /stylist/result/[id], /stylist, /stylist/intake, /stylist/chat, /stylist/admin.
Layer 02
Auth + Billing
Supabase Auth with magic links. Stripe for annual/monthly plans, coupons, failed payment webhooks, refunds, and renewal events.
Layer 03
Database
Supabase Postgres. Structured member profile is the master document. pgvector for chat and letter memory retrieval.
Layer 04
Admin Dashboard
Build native inside /stylist/admin or use Retool for beta. Must include role-based access, audit logs, queues, filters, and exports.
Layer 05
Email + DM
Resend/Postmark for email. ManyChat for Instagram comment-to-DM. All links use UTMs and reel IDs.
Layer 06
Analytics
PostHog or Segment-style event tracking. Meta Pixel + CAPI for paid attribution. Admin dashboard uses internal event tables as source of truth.
Layer 07
Generation + QA
Model-generated drafts for Blueprint, chat, and letters. Human review for beta Blueprints and flagged interactions. Voice post-processing layer before user-facing output.
Layer 08
Storage
Supabase Storage for photos and PDFs. Strict access controls. Signed URLs. Assets linked to member ID and usage context.

13 · Risks

What could kill this version.

The revised model reduces build risk, but the business still dies if retention is fake, tracking is poor, or the product feels generic.

Critical

People buy the Blueprint, not the membership

If usage drops after the first diagnostic, annual renewal will be weak.

MitigationMeasure first 30-day activation before public scale. Weekly letters must create fresh value, not repeat the Blueprint.
Critical

Admin tracking is incomplete

If source, status, usage, and health score are missing, you cannot manage CAC or retention.

MitigationBuild admin states and event tracking before scaling paid ads.
High

Chat sounds generic

Members churn if answers feel like generic internet styling advice.

MitigationVoice QA, memory recall tests, and mandatory methodology references.
High

Too much human review

Margins collapse if every chat and letter needs manual editing.

Mitigation100% review only in beta; later review flagged items and random samples.
Medium

Content attracts wrong geography

A viral Reel in India does not validate a US/UK/Canada price point.

MitigationTrack country at every step and judge funnel metrics by target geography.
Medium

Usage limits feel restrictive

Some users may object to limits.

MitigationFrame limits as “stylist questions/photo checks” not credits. Allow soft grace for high-value members.
